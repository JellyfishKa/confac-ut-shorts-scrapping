# confac-ut-shorts-scrapping

Metadata-first инструмент для поиска коротких видео по выбранным площадкам, сравнения доступных метрик и выборочного скачивания в контент-пайплайне.

Основная идея проекта — максимально долго работать только с метаданными и скачивать исходное видео лишь тогда, когда оно действительно требуется для последующей обработки.

## Что реализовано

- поиск кандидатов по теме через YouTube Data API v3 и публичную выдачу Rutube;
- выбор одной или нескольких площадок для общего поиска с отдельным статусом каждой;
- подготовленные поисковые адаптеры VK Клипов, TikTok и Instagram Reels при наличии нужного доступа к бесплатным API;
- ручной импорт прямой ссылки на VK Клип, TikTok, Instagram Reel или видео Rutube через `yt-dlp` без скачивания MP4;
- получение публичных метаданных видео и каналов;
- фильтрация по возрасту, длительности, просмотрам и engagement-метрикам;
- расчёт производных метрик для сравнения роликов;
- сохранение повторных наблюдений в SQLite;
- фоновый трекер, который сам перепроверяет найденные ролики по ID;
- кнопка «Хайп», которая выбирает самые быстрорастущие ролики среди найденных;
- расчёт фактического роста просмотров между snapshot'ами;
- экспорт результатов в CSV и JSON;
- формирование нейтрального JSON-manifest для передачи данных в ComfyUI;
- выборочное скачивание финалистов через `yt-dlp`;
- анализ сюжета выбранного ролика через Gemini с экспортом JSON;
- Jupyter Notebook для анализа результатов и построения графиков.

## Архитектура

```text
YouTube Data API
       ↓
public metadata
       ↓
SQLite snapshots ─────→ growth metrics
       ↓
filter + scoring
       ↓
shortlist
       ↓
CSV / JSON / Jupyter / ComfyUI manifest
       ↓
        ├── metadata-only workflow → без скачивания
        │
        └── video-level workflow → yt-dlp → local MP4
```

Такой подход позволяет сначала обработать десятки кандидатов по дешёвым данным и скачивать только несколько роликов, которым нужен анализ кадров, аудио, OCR, транскрибация или другой video-level processing.

## Используемые данные

### Публичные метаданные

Для каждого кандидата сохраняются:

```text
video_id
url
title
description
channel_title
published_at
duration_seconds
views
likes
comments
subscribers
thumbnail_url
```

Количество подписчиков может отсутствовать, если канал не предоставляет его публично.

### Производные метрики

`age_hours`

Возраст ролика в часах.

`views_per_hour`

```text
views / age_hours
```

Средняя скорость набора просмотров с момента публикации.

`like_rate`

```text
likes / views
```

`comment_rate`

```text
comments / views
```

`breakout_ratio`

```text
views / subscribers
```

Показывает масштаб ролика относительно размера канала. Метрика недоступна, если число подписчиков скрыто.

`growth_views_per_hour`

```text
(current_views - previous_views) / elapsed_hours
```

Рассчитывается после повторного наблюдения того же видео и отражает фактическую скорость роста между двумя snapshot'ами. Текущее наблюдение сравнивается с последним snapshot'ом не моложе `GROWTH_MIN_INTERVAL_MINUTES` (по умолчанию 30 минут): при более частых повторах изменение просмотров в основном отражает задержку обновления счётчиков, а не рост. Snapshot записывается при каждом поиске, в том числе для роликов, не прошедших фильтры, чтобы у них была база для сравнения.

`popularity_score`

Конфигурируемая эвристическая оценка для сортировки кандидатов. На текущем этапе она не является моделью прогнозирования виральности и предназначена только для предварительного ранжирования.

Оценка складывается из `views_per_hour`, `like_rate` и `comment_rate` с весами `WEIGHT_*` из `.env`. Без `views_per_hour` оценка не считается. Если площадка не сообщила лайки или комментарии, их вес распределяется между оставшимися метриками: например, у Rutube оценка отражает только скорость просмотров. Поэтому оценки площадок с разным набором метрик сравнимы лишь приблизительно.

## Почему используются snapshot'ы

`views_per_hour` показывает среднюю скорость за всё время существования ролика. Для поиска роликов, которые ускоряются прямо сейчас, этого недостаточно.

Поэтому каждый поиск сохраняет наблюдение в SQLite:

```text
video_id
observed_at
views
likes
comments
```

При следующем появлении того же ролика можно вычислить изменение метрик за фактический интервал времени.

База создаётся автоматически:

```text
data/snapshots.sqlite3
```

## Трекер роста

Повторять поиск вручную не нужно. Каждый ролик, прошедший фильтры поиска или добавленный по ссылке, попадает в отслеживаемые на `TRACKER_HOURS` (по умолчанию 48 часов); повторное появление в поиске продлевает срок. Пока сервер запущен, трекер раз в `TRACKER_INTERVAL_MINUTES` (по умолчанию 30 минут) заново запрашивает счётчики этих роликов по ID и записывает snapshot, из которого считается `Δ views/h`.

| Площадка | Как обновляется | Стоимость |
| --- | --- | --- |
| YouTube | `videos.list`, до 50 роликов за запрос | 1 единица квоты на 50 роликов против 100 за поиск |
| Rutube | публичный `/api/video/{id}/` | один запрос на ролик, только просмотры |
| VK, TikTok, Instagram | публичная страница ролика через `yt-dlp` | несколько секунд на ролик; может не сработать, если площадка требует вход |

Ролики без просмотров (Instagram из поиска по хештегу) не отслеживаются. Если площадка не ответила или ролик удалён, причина видна в блоке «Отслеживаемые», а следующая попытка будет через интервал.

В интерфейсе блок «Отслеживаемые» показывает текущие просмотры, `Δ views/h`, мини-график просмотров по snapshot'ам и время последней проверки. Ролик можно закрепить — тогда он отслеживается без срока — или убрать; собранные snapshot'ы при этом сохраняются.

Трекер работает только вместе с сервером. Чтобы собирать данные без открытого приложения, выключите фоновый цикл (`TRACKER_ENABLED=false`) и запускайте один проход из планировщика задач Windows или cron:

```powershell
.\.venv\Scripts\python.exe -m app.tracker
```

## Кнопка «Хайп»

Кнопка **Хайп** рядом с поиском выбирает 5 самых быстрорастущих роликов среди всех отслеживаемых — то есть среди всего, что нашли поиски за последние `TRACKER_HOURS`.

Сначала отсеивается мусор: ролики меньше чем с `HYPE_MIN_VIEWS` просмотров (по умолчанию 1000) и ролики, которые сейчас не набирают просмотры. Остальные получают оценку хайпа от 0 до 100 — место ролика среди найденных по пяти признакам:

| Признак | Вес | Откуда |
| --- | --- | --- |
| Текущая скорость | 40% | `Δ views/h` трекера, иначе средние `views/h` |
| Ускорение | 25% | рост за последний интервал против предыдущего, по истории snapshot'ов |
| Лайки | 15% | `like_rate` |
| Охват сверх подписчиков | 10% | `breakout_ratio` (YouTube) |
| Свежесть | 10% | возраст ролика |

Оценка относительная: она показывает лучших среди найденного, а не абсолютную виральность. Признак, которого у ролика нет, отдаёт свой вес остальным. Ускорение появляется после трёх snapshot'ов с интервалами не меньше `GROWTH_MIN_INTERVAL_MINUTES`, то есть примерно через час работы трекера. Под каждой карточкой написано, почему ролик попал в подборку, и есть кнопки **Сюжет**, **Comfy JSON** и **MP4**.

API: `GET /api/hype?limit=5` (от 1 до 20) возвращает `considered` — сколько роликов прошло фильтр мусора — и `picks` с `hype_score`, `acceleration` и `reasons`.

### Поиск по нескольким площадкам

Выберите площадки над кнопкой поиска. Результаты собираются одновременно, объединяются в одной таблице и показывают источник каждого ролика. Таблица сортируется по текущей скорости: `Δ views/h`, если есть повторный snapshot, иначе `views/h`; при равенстве — по `popularity_score`. Если одна площадка не ответила или требует доступ, результаты остальных сохраняются, а причина видна рядом с названием источника.

| Площадка | Поиск по теме | Что нужно |
| --- | --- | --- |
| YouTube Shorts | Да | `YOUTUBE_API_KEY` |
| Rutube | Да, по публичной выдаче с фильтром короткой длительности | Без ключа |
| VK Клипы | Через `video.search`, после проверки с вашим токеном | `VK_ACCESS_TOKEN` |
| TikTok | Через Research API, если проект одобрен TikTok | Доступ `research.data.basic` и ключи клиента |
| Instagram Reels | По одному хештегу, если Meta разрешила доступ | Профессиональный IG аккаунт, ID и токен Graph API |

Поля для доступа добавляются в серверный `.env` по образцу `.env.example`: `VK_ACCESS_TOKEN`; `TIKTOK_CLIENT_KEY` и `TIKTOK_CLIENT_SECRET` одобренного Research-проекта (либо временный `TIKTOK_RESEARCH_TOKEN`); `INSTAGRAM_USER_ID` и `INSTAGRAM_ACCESS_TOKEN`. Ключи не вводятся в браузере. После изменения `.env` перезапустите сервер. Без нужного доступа источник показывает статус «нужен доступ к API», остальные выбранные площадки продолжают поиск.

Поиск TikTok через [Research API](https://developers.tiktok.com/docs/en/research-api-specs-query-videos) может запаздывать и требует [одобрения проекта](https://developers.tiktok.com/docs/en/research-api-faq). Instagram через [Graph API](https://www.postman.com/meta/instagram/documentation/6yqw8pt/instagram-api) ищет один хештег, а не произвольную фразу; для него оставьте пустыми фильтры по просмотрам и лайкам. VK использует [метод `video.search`](https://dev.vk.com/method/video.search) и фильтрует тип `short_video`. Публичная выдача Rutube проверена реальным запросом, но стабильность этого маршрута площадкой не гарантирована. Поиск с токенами VK/TikTok/Instagram пока проверен тестами с имитацией ответа, а не живыми запросами.

Если поля просмотров, лайков или времени публикации не получены, они остаются пустыми и не участвуют в расчёте соответствующей метрики. Сравнивайте `views/h` между площадками как ориентир: источники по-разному считают и обновляют просмотры. Для первых проверок Rutube удобно поставить `Мин. views = 0`, `Макс. возраст = 8760` и искать `шортс`: обычные фильтры YouTube могут отсечь всю выдачу.

### Ролики из других площадок по ссылке

Поле **Добавить по ссылке** принимает ссылку на один публичный ролик VK Клипы, TikTok, Instagram Reels или Rutube. Приложение считывает доступные метаданные и добавляет видео в общий список; MP4 на этом шаге не скачивается. Кнопка **MP4** позволяет отдельно скачать выбранный ролик. Если площадка не отдаёт просмотры, лайки или время публикации, поле остаётся пустым: ноль не подставляется и рейтинг не вычисляется по выдуманным данным.

Добавление по ссылке остаётся запасным способом для конкретного ролика. Некоторые ролики могут быть недоступны `yt-dlp` из-за ограничений платформы, региона или требования входа; поддержку каждой площадки нужно проверить на реальных ссылках. Подробнее: [список поддерживаемых сайтов yt-dlp](https://github.com/yt-dlp/yt-dlp/blob/master/supportedsites.md).

Кнопка **Сюжет** показывает хронологическое описание от Gemini, которое можно скопировать или скачать в JSON. Для YouTube сервису передаётся публичная ссылка. Для VK, TikTok, Instagram и Rutube приложение сначала скачивает выбранный MP4 после подтверждения, а затем отправляет его содержимое в Google Gemini. Принимаются файлы из папки загрузок приложения размером до 14 МиБ и длительностью до 180 секунд; файл должен быть скачан через приложение для той же ссылки. Связь ссылки и файла хранится в `data/downloads.sqlite3` и сохраняется после перезапуска сервера. `GEMINI_API_KEY` хранится только на сервере в `.env`. Анализ может занимать время и расходовать квоту Gemini; факты, цитаты и таймкоды нужно сверять с оригиналом.

### Как пользоваться анализом видео

1. Выполните поиск и выберите один ролик из списка.
2. Нажмите **Сюжет**. Для ролика из соцсети подтвердите скачивание и отправку MP4 в Gemini. Если MP4 уже скачан этой сессией, используется его локальный путь. Описание и различимые реплики — черновик, а не дословная расшифровка.
3. Сверьте важные события, цитаты и таймкоды с оригиналом. Если нужен исходник для дальнейшей обработки, нажмите **MP4** только у выбранного видео.
4. Сохраните JSON сюжета отдельно от CSV/JSON с метриками: метрики отвечают за отбор, сюжет — за содержание ролика.

Если Gemini сообщает о перегрузке, попробуйте повторить запрос позже. Действительный ключ не гарантирует доступность модели в конкретный момент. После изменения `.env` перезапустите сервер.

Для коротких абсурдных AI-роликов описание помогает разобрать референс: персонажей, превращения, реплики, неожиданный поворот и финальный гэг. Новый сценарий или промпт по мотивам референсов — отдельная задача следующего этапа; текущий ответ остаётся разбором того, что действительно есть в видео.

### AutoClip и точные реплики

Для дословных реплик нужен отдельный источник текста: субтитры автора либо распознавание звука. [Gemini Transcribe](https://ai.google.dev/gemini-api/docs/transcribe) принимает загруженный аудиофайл и поддерживает таймкоды и разделение говорящих; локальный Whisper — вариант без облачного распознавания. Текущий `/api/story` описывает видео, но не возвращает проверенную дословную расшифровку. Отдельная транскрибация и редактор SRT пока не подключены.

Для выбранного ролика уже есть явный путь передачи: скачайте его кнопкой **MP4**, установите и настройте [AutoClip](https://github.com/zhouxiaoka/autoclip/blob/main/docs/CLI_AND_MCP.md) отдельно, затем запустите из корня проекта:

```powershell
.\.venv\Scripts\python.exe -X utf8 scripts\autoclip_handoff.py "downloads\VIDEO_ID.mp4" --platform youtube_shorts --autoclip "C:\Users\Sergej\Documents\Codex\autoclip-runtime\.venv\Scripts\autoclip.exe" --use-project-gemini
```

Путь к MP4 возьмите из сообщения после скачивания. `--autoclip` указывает на отдельную установку AutoClip 1.5.7 в этом рабочем окружении; на другом компьютере замените путь. `--use-project-gemini` берёт `GEMINI_API_KEY` из `.env` только при явном запуске, передаёт его AutoClip через окружение и выбирает модель `gemini-3.5-flash-lite`. Это отправляет выбранный MP4 и данные анализа в Google Gemini и может расходовать квоту. Если настроите в AutoClip собственную модель, уберите флаг. Проверенный SRT можно передать через `--srt "C:\path\to\transcript.srt"`; без SRT AutoClip использует локальное распознавание. Скрипт принимает MP4 только из `downloads` и выводит результат после фактической обработки. CLI, FFmpeg, локальное распознавание и подключение к указанной модели проверены; реальная нарезка пока не запускалась, поскольку нет выбранного MP4. Для уже короткого ролика полезных фрагментов может не быть.

План следующего этапа для дословных реплик: MP4/аудио → транскрипт с таймкодами → ручная сверка → SRT → AutoClip. Детали формата и проверки описаны в [`research/video-analysis-handoff.md`](research/video-analysis-handoff.md).

## Получение YouTube Data API key

Для доступа к публичным метаданным достаточно обычного API key; OAuth на текущем этапе не требуется.

1. Создайте или выберите проект в Google Cloud Console.
2. Откройте **APIs & Services → Library**.
3. Включите **YouTube Data API v3**.
4. Откройте **APIs & Services → Credentials**.
5. Выберите **Create credentials → API key**.
6. Сохраните ключ в `.env`.
7. Рекомендуется ограничить ключ только API `YouTube Data API v3`.

Документация Google:

- https://developers.google.com/youtube/v3/getting-started
- https://developers.google.com/youtube/registering_an_application
- https://docs.cloud.google.com/docs/authentication/api-keys

## Сценарий демонстрации

1. Запустить приложение и выполнить поиск по теме, например `AI tools`.
2. Показать, что список кандидатов и их метрики получены без скачивания MP4.
3. Сравнить кандидатов по `views/h`, `like rate`, `comment rate`, `breakout` и `score`.
4. Экспортировать текущую выборку в CSV или JSON.
5. Сформировать `Comfy JSON` для выбранного кандидата.
6. Через 30+ минут показать в блоке «Отслеживаемые» появившийся `Δ views/h` и мини-график: трекер обновляет ролики сам.
7. Скачать MP4 только для выбранного финалиста, если downstream-пайплайну действительно требуется видео.

## ComfyUI integration

Endpoint `POST /api/comfy/manifest` формирует workflow-agnostic manifest. Collector не зависит от конкретных node ID внутри ComfyUI workflow.

Пример структуры:

```json
{
  "source": {
    "url": "https://www.youtube.com/shorts/VIDEO_ID",
    "local_video_path": null,
    "title": "...",
    "description": "..."
  },
  "virality": {
    "views": 250000,
    "views_per_hour": 12000,
    "growth_views_per_hour": 18000,
    "like_rate": 0.052,
    "comment_rate": 0.004,
    "breakout_ratio": 12.4,
    "popularity_score": 0.81
  },
  "comfyui_inputs": {
    "source_url": "...",
    "source_video_path": null,
    "source_title": "...",
    "virality_score": 0.81
  }
}
```

Пока workflow в ComfyUI меняется, manifest выступает стабильным промежуточным контрактом. После стабилизации workflow можно добавить adapter, который сопоставит поля manifest с конкретными input-полями API-format workflow и отправит его в ComfyUI через `/prompt`.

Подробности: [`research/comfyui-handoff.md`](research/comfyui-handoff.md).

## API

### Проверка состояния

```http
GET /health
```

### Поиск, фильтрация и snapshot

```http
POST /api/search
```

Пример:

```json
{
  "query": "AI tools",
  "platforms": ["youtube", "rutube"],
  "max_age_hours": 168,
  "min_views": 1000,
  "min_views_per_hour": 0,
  "min_like_rate": 0,
  "max_duration_seconds": 180,
  "limit": 15
}
```

Если `platforms` не указано, поиск остаётся только по YouTube для совместимости со старыми запросами. В ответе поле `platform_statuses` показывает найденное число, итоговое число и ошибку или ограничение отдельно для каждого выбранного источника.

### Формирование ComfyUI manifest

```http
POST /api/comfy/manifest
```

```json
{
  "video": {"...": "candidate returned by /api/search"},
  "local_video_path": null
}
```

### Скачивание выбранного видео

```http
POST /api/download
```

```json
{
  "url": "https://www.youtube.com/shorts/VIDEO_ID"
}
```

Принимаются ссылки YouTube и прямые ссылки на один ролик VK, TikTok, Instagram Reels или Rutube; другие адреса отклоняются с HTTP 422. Если `yt-dlp` не смог скачать ролик, ответ приходит с HTTP 502 и `{"status": "failed", "error": "..."}`.

### Сюжет выбранного видео

```http
POST /api/story
```

```json
{
  "url": "https://www.youtube.com/shorts/VIDEO_ID"
}
```

Для ролика VK, TikTok, Instagram или Rutube передайте путь к ранее скачанному через приложение MP4:

```json
{
  "url": "https://rutube.ru/video/VIDEO_ID/",
  "local_video_path": "C:\\path\\to\\downloads\\VIDEO_ID.mp4"
}
```

### Импорт одного ролика по ссылке

```http
POST /api/import
```

```json
{
  "url": "https://www.instagram.com/reel/VIDEO_ID/"
}
```

Возвращает `video` в формате кандидата. Поле `platform` различает источники; статистика может отсутствовать. Для сюжета ролика из соцсети требуется скачать выбранный MP4 и отправить его в Gemini через `/api/story`.

### Отслеживаемые ролики

```http
GET /api/tracked
```

Возвращает `interval_minutes`, `tracked_hours` и `videos`: для каждого ролика последние данные кандидата, `pinned`, `tracked_until`, `last_checked_at`, `last_error` и `history` — просмотры по snapshot'ам.

```http
POST /api/tracked/pin
```

```json
{"platform": "youtube", "video_id": "VIDEO_ID", "pinned": true}
```

```http
DELETE /api/tracked/{platform}/{video_id}
```

Прекращает отслеживание; snapshot'ы остаются в базе. Для неотслеживаемого ролика оба метода возвращают 404.

## Ограничения текущего MVP

- YouTube Data API не возвращает публичный флаг `isShort`; используется фильтр длительности и `videoDuration=short` на этапе поиска.
- Для первого наблюдения невозможно вычислить фактический growth rate — требуется минимум два snapshot'а с интервалом не меньше `GROWTH_MIN_INTERVAL_MINUTES`.
- `popularity_score` пока является эвристикой и требует калибровки на накопленных данных.
- Недоступные просмотры, лайки и комментарии не заменяются нулями: соответствующие производные метрики остаются пустыми, а неизвестная метрика не проходит фильтр с положительным порогом. Это касается Rutube и Instagram, а также роликов YouTube со скрытыми лайками или выключенными комментариями. У Instagram нет просмотров, поэтому нет и `popularity_score`. Rutube, VK и YouTube с неполными счётчиками сохраняют отдельные снимки просмотров: повторный поиск показывает `growth_views_per_hour`, но не рост лайков. TikTok и VK с полными счётчиками сохраняют просмотры, лайки и комментарии. Instagram не отдаёт статистику чужих Reels в поиске по хештегу, поэтому прирост для них недоступен.
- Audience retention чужих видео недоступен через публичный YouTube Data API.
- `yt-dlp` зависит от текущего поведения YouTube и периодически требует обновлений.
- Hypit пока не является частью runtime-пайплайна. Потенциальное применение — структурный анализ небольшого числа выбранных референсов после metadata-first отбора.
